# S3-compatible object storage Provider

The `s3` type-id: read-only browsing of buckets, folders and objects, object metadata and capped previews over the S3 REST API, verified on MinIO RELEASE.2025-10-15T17-29-55Z, Silo RELEASE.2026-09-16T00-00-00Z, Garage v2.4.1 and RustFS 1.0.1, and not on AWS S3 or any hosted service.
Source: [`src/lib/db/providers/objectstore/s3/`](../../src/lib/db/providers/objectstore/s3/).
Tests: [`tests/unit/db/s3/`](../../tests/unit/db/s3/) and [`tests/integration/db/s3-provider.test.ts`](../../tests/integration/db/s3-provider.test.ts).

## Before you connect

Seven facts decide whether the first connection works.

1. Type the server's S3 API address, not its web console's: Endpoint host and Port, or paste `http://host:port` or `https://host:port` into Endpoint host.
   Where Studio runs decides what to type in Endpoint host:

| Where the server and Studio run | Endpoint host |
|---|---|
| Both on this machine | `localhost` |
| The server on this machine, Studio in Docker | `host.docker.internal`; on Linux, start Studio's container with `--add-host=host.docker.internal:host-gateway` |
| The server elsewhere | its address, over TLS |

2. Studio addresses every object as `<endpoint>/<bucket>/<key>`, path style, and never by a bucket host name, so a server that answers only virtual-hosted requests cannot be read.
3. Region: Studio signs for `us-east-1` unless you type another region. A server that keeps a fixed region refuses a request signed for any other, and only some servers name the region they expect in the error; section 4.4 says which of the verified servers enforce a region and which name it.
4. Credentials: put the access key ID in Access key ID and the secret access key in Secret access key.
   Only the keys you type sign a request: Studio never reads the server's environment, shared credential files or instance role, and with both fields empty it sends unsigned requests, which only a public bucket answers, and Garage answers none.
   Temporary credentials that need a session token cannot be used in this version.
5. Bucket: leave it empty to list every bucket the credential may list, or name one bucket to browse only that one. This is a convenience, not a boundary (section 13).
   MinIO, Silo, Garage and RustFS list a limited key's own buckets; AWS S3 and some hosted services refuse the listing to such a key (not verified here), so name the bucket there.
6. TLS: Studio refuses plain HTTP to a host that is neither this machine nor reached through an SSH tunnel unless you tick Connect without TLS, because bucket and object names, listings and previews cross the network in the clear, and anyone who captures a signed request can send it again for minutes, and on some servers for hours.
7. What this version does not do: write, run SQL over files, sign with temporary credentials, or use virtual-hosted addressing; and it has been verified on MinIO, Silo, Garage and RustFS only, not on AWS S3, a hosted service or any other server.

## 1. Overview

Studio reads buckets in the tree, folders and objects in the Keys panel, an object in the Source tab with its metadata and a capped preview, and one AWS CLI read command per run in the editor.
It writes nothing, whatever the connection's Read-only box says.
The embedded workspace has no Keys panel, so there the console is the only way to reach an object, as etcd documents for its keys ([etcd.md](./etcd.md), section 6.4).

| An object | The key-browser object kind, opened in the Source tab |
| Object metadata | The Metadata part of the Source tab |

### 2.3 Registration & lifecycle

`createDatabaseProvider()` ([`factory.ts`](../../src/lib/db/factory.ts)) builds the provider for the type-id `s3` through a dynamic import.
`connect()` builds the session's options, refuses before any request what section 4 says it refuses, builds the byte transport and sends the probe of section 7; a session is kept only after its probe parsed as S3 XML.
`disconnect()` aborts every request in flight and closes the transport.

### 2.4 The client, and why

Requests go through the shared `node:http(s)` byte transport, extended with an opt-in signing hook, HEAD and a byte body, and are signed by Studio's own SigV4 module over `node:crypto`, tested on the AWS suite vectors.
Answers are read by a narrow XML reader of Studio's own that refuses a document type declaration and every entity.
There is no AWS SDK: its default credential chain reads the server's own identity, from the environment, shared files, a container endpoint or instance metadata, which section 3.2 rules out.

## 3. Design decisions

Each decision below states the reason for it.

### 3.1 Read-only v1

Studio reads S3 and writes nothing, whatever the connection's Read-only box says.
The client is built over the byte transport's method set of GET and HEAD alone, so no code path can send a write ([row 3.18](../SECURITY.md)).
Writes are a backlog entry ([D264](../BACKLOG.md)), and so is SQL over files ([D261](../BACKLOG.md)).

### 3.2 Only typed credentials sign

A request is signed only with the access key pair typed into the connection.
Studio never reads an environment variable, a shared credential or config file, a container credential endpoint or instance metadata, so a connection never borrows the identity of the machine Studio runs on ([row 3.19](../SECURITY.md)).
With both keys empty the request goes unsigned: that is what an empty pair means, and there is no separate anonymous mode.

### 3.3 Path style and the region

Every request is addressed as `<endpoint>/<bucket>/<key>`, path style, because the shared transport pins one origin per connection and a virtual-hosted request has one origin per bucket.
The Region field names the region every request is signed for; empty means `us-east-1`.
Section 4.4 says which verified server enforces a region and which names the one it expects.

### 3.4 Link-local networks are always refused

The byte transport S3 uses refuses an endpoint that is, or resolves to, an address in one of the four entries of `LINK_LOCAL_NETWORKS`: `169.254.0.0/16` (also in its IPv4-mapped form), `fe80::/10`, `fd00:ec2::254/128` and `64:ff9b::a9fe:0/112` (the NAT64 form of `169.254.0.0/16`), whatever `DB_HTTP_BLOCK_PRIVATE_HOSTS` says ([row 0.6](../SECURITY.md)).
AWS, Azure and Google Cloud serve instance metadata at `169.254.169.254`, and AWS also at `fd00:ec2::254`, so a path-style GET there would read instance credentials as an object.
Through an SSH tunnel, the far end's address literal is checked the same way; a far end given as a name is resolved by the SSH server.
Loopback, private and CGNAT addresses stay reachable, so local servers work; a metadata service a cloud serves outside these networks is not refused, and none is claimed.

### 3.5 The read-only mode

`READ_ONLY_ENFORCED.s3` is true, so a seed may set `readOnly: true` on an S3 connection, and the connection refuses nothing it would not refuse anyway: S3's provider runs reads only.
The dialog says so under the Read-only box: S3-compatible connections are read-only in this version, whether or not this is ticked: Studio sends no write.
A read-only seed that carries the documented default MinIO or RustFS credential is refused at connect, because the mode would promise a boundary the server does not keep.

### 3.6 Machine access

No agent execution and no MCP: `MCP_EXPOSABLE.s3` is false, so a seed with `mcp: true` on an S3 connection fails the whole file, and the provider implements no `queryReadOnly`, so agent execution and MCP `run_read_query` refuse it, because no MCP surface that lists buckets but never returns an object key is designed yet.
Plan mode works: it grounds on the bucket names the tree shows and drafts one console command in an `s3` block, which it never runs; no object key, prefix, size or content reaches the model.
[B104](../BACKLOG.md) records what an MCP surface and agent execution would need.

### 3.7 The Keys panel cursor

A Keys panel page's cursor is Studio's own envelope around the server's continuation token, because MinIO, Silo and RustFS accept a forged token as a start position.
It is a stateless, scope-bound envelope with no MAC: it is bound to its bucket, prefix and level, and Studio refuses a cursor of another shape or scope before any request.
It holds no per-process state, so it is valid in every process that serves the connection, across a restart, an idle eviction and another replica.
It carries a position, not an authority: a hand-written cursor of the right shape and scope can reach the server, which can only start the listing at another position inside what the key may list, and the server's 400 or 501 for it is reported as the error table's continuation-token row.

## 4. Connection

A connection is one S3 endpoint, an optional key pair, a region and an optional bucket.

### 4.1 Configuration fields

| Dialog field | Connection field | Classification | What it is |
|---|---|---|---|
| Endpoint host, Port | `host`, `port` | public | The S3 API endpoint; the default port is the provider's declared `defaultPort`, `9000` |
| SSL mode, CA | `ssl` | public | TLS; a pasted `https://` raises SSL mode without lowering it |
| Access key ID | `user` | public, shown in the clear and part of the connection fingerprint | The access key ID, 3 to 512 characters; outside that range it is refused before any request with the one sentence the provider and the form share; empty with the secret empty means unsigned requests |
| Secret access key | `password` | secret | Never sent to the S3 server: Studio's server signs each request with it |
| Region | `region` (new, S3 only) | public | Defaults to `us-east-1` when empty |
| Bucket | `database` | public | Optional; when set, Studio never lists buckets |
| Connect without TLS | `allowInsecureAuth` | public | The per-connection consent of section 4.6, signed or unsigned alike |
| Read-only | `readOnly` | public | Accepted; Studio reads only whatever it says (section 3.5) |

The dialog's hint under each field:

- Endpoint host: A host name or address, or a pasted http:// or https:// endpoint such as http://localhost:9000, which is split into Host and Port. The endpoint only: a bucket goes under Bucket, never in the address. MinIO and RustFS serve on port 9000 unless configured otherwise, Garage on 3900. If Studio runs in a container, localhost is that container: use host.docker.internal.
- Access key ID: The access key ID. It is stored and shown in the clear, like a user name. Leave both keys empty only for a bucket that allows anonymous reads: Studio then sends unsigned requests, never this server's own cloud credentials.
- Secret access key: The secret access key. Studio's server signs every request with it and never sends it to the S3 server. Fill in both keys, or neither.
- Bucket: Optional. With a bucket here, Studio reads only that bucket and never lists the others, which a key limited to one bucket needs. Empty: every bucket this key can list.
- Region: The region every request is signed for. Empty means us-east-1, which MinIO accepts unless it was started with a region of its own. Garage: its s3_region setting. AWS: the bucket's region.
- Connect without TLS: Ticked, Studio connects to this host over plain HTTP. The secret access key is never sent to this server, but bucket and object names, listings and previewed contents travel in the clear, readable by anyone on the path, and a captured request can be replayed for several minutes. Choose an SSL mode under SSL / TLS, or an SSH tunnel, wherever the server offers one.

Values the provider refuses before any request, with the sentence the dialog and the provider share:

- An access key ID with a space, comma, equals sign or slash: Access key ID must be printable ASCII without spaces, commas, equals signs or slashes, because it is sent inside the signed Authorization header. Nothing was sent.
- An access key ID shorter than 3 or longer than 512 characters: Access key ID holds 3 to 512 characters, because S3 servers issue no shorter ID and it is sent inside the signed Authorization header. Nothing was sent.
- A bucket name Studio cannot address in path style: Bucket must be 1 to 255 letters, digits, dots, hyphens or underscores, starting and ending with a letter or digit. Nothing was sent.
- A region that is not a region name: Region must be 1 to 64 letters, digits, hyphens or underscores, such as us-east-1. Nothing was sent.

The access key ID stays a public field, and it is still withheld from any server text an error quotes (section 10).

### 4.2 Authentication

Fill in both keys to sign every request with AWS Signature Version 4, or leave both empty to send unsigned requests.
One key without the other is refused before any request: Access key ID and Secret access key go together: fill in both to sign requests, or clear both to send unsigned requests. Nothing was sent.
Studio signs with its own SigV4 code over `node:crypto`, signing `host`, `range` when sent, and every `x-amz-*` header it sends, with the payload hash of an empty body.
The dialog warns when the pair is the documented default root credential of MinIO (`minioadmin`) or RustFS (`rustfsadmin`).
Temporary credentials need a session token, which this version cannot send ([D262](../BACKLOG.md)).

### 4.3 TLS

The SSL panel is the shared one: `disable`, `require`, `verify-system`, `verify-ca`, `verify-full`, with a custom CA and a client certificate.
TLS mode `require` sends signed requests to an unverified peer.

### 4.4 One endpoint, path style and the region

One connection is one S3 endpoint, and every bucket is addressed under it in path style ([D263](../BACKLOG.md)).
The Region field signs every request for its value, `us-east-1` when empty.

| Server | Region enforced | Region named in the error |
|---|---|---|
| MinIO | No, unless started with `MINIO_SITE_REGION`; then Yes for bucket and object reads | Yes, when a site region is set |
| Silo | No, unless started with `MINIO_SITE_REGION`; then Yes for bucket and object reads | Yes, when a site region is set |
| Garage | Yes, on every request, ListBuckets included: its `s3_region` | Yes, on a GET |
| RustFS | No | No |

### 4.5 SSH tunnel

The dialog offers the SSH tunnel on every S3-compatible object storage connection.
Through a tunnel, the signed and sent Host is the local forward, so a server behind the tunnel that routes by Host name is not supported in v1 (row A63's outcome).
A far end given as a name is resolved by the SSH server, where Studio cannot check it; a far end given as an address literal is checked against the link-local networks of section 3.4 before anything is forwarded to it.
The SSH session to the bastion is already open by then, so a refused far end still costs one SSH login, and Studio closes the tunnel it opened for the refused connection.

### 4.6 Plain HTTP off this machine needs consent

Studio refuses plain HTTP to a host that is neither a loopback address nor reached through an SSH tunnel, signed or unsigned alike, unless the connection's Connect without TLS box is ticked:
This connection would reach a host that is not this machine over plain HTTP, where anyone on the path can read bucket and object names, listings and previews, and replay a signed request. Choose an SSL mode under SSL / TLS, connect through an SSH tunnel, or tick Connect without TLS. Nothing was sent.
The secret access key never crosses the network either way; what crosses it in the clear is every name, listing and preview, and a signed request anyone who captures it can send again while the server's clock window lasts.

### 4.7 Pasting an address

Endpoint host takes a pasted `http://` or `https://` address and splits it into Host and Port; `https://` raises an SSL mode of `disable` to `verify-system`, and `http://` keeps the mode.
An address with a path is refused, because a bucket goes under Bucket; an `s3://bucket/key` URI names an object, not an endpoint, and is refused too.
The connection-string box offers no S3 mode.

Caveats the live pass confirmed, per server:

| Server | Caveat |

### 4.9 What is not verified

Studio has not been run against AWS S3, any hosted S3-compatible service, or any self-hosted server other than the four of section 4.8, such as Ceph RGW or SeaweedFS, so none of them is claimed.
These behaviours exist on AWS and were never exercised:

- a `301 PermanentRedirect` for a bucket in another region, which Studio refuses rather than follows;
- virtual-hosted addressing on real DNS, and bucket names with dots over TLS;
- temporary credentials from STS, which need a session token Studio cannot send;
- ListBuckets paging, which AWS requires above 10,000 buckets and every verified server ignores;
- objects in an archive storage class, which answer a read with `403 InvalidObjectState`;
- the checksum headers AWS SDKs send by default;
- keys with `.`, `..` or `//` segments, which AWS accepts and MinIO, Silo and RustFS refuse.

Cloudflare R2 signs for the region `auto`, and DigitalOcean Spaces asks clients to sign for `us-east-1`; neither was tried.
[D265](../BACKLOG.md) is the follow-up.

## 5. Query interface

The editor runs one AWS CLI read command per run, or Studio's own `preview`.

### 5.1 The command

The editor holds one AWS CLI read command per run, written as the AWS CLI writes it, read as POSIX shell words by the shared reader `src/lib/db/console/shell-words.ts`, the rule Oxia's console follows.
A leading `$` or `%` prompt and the word `aws` are stripped only when they stand bare; global options may come anywhere after them.
A line ending in a backslash continues on the next line; a `^` line continuation, an environment assignment such as `AWS_PROFILE=prod aws s3 ls`, a pipe, a redirect and a second command are refused before any request.
Studio's own `preview` is written without `aws`, so a line that starts with `aws` always pastes into the real AWS CLI.

### 5.2 Commands and flags

| Command | Flags |
|---|---|
| `aws s3 ls [PATH]` | `--recursive` (no value); `--page-size` (1 to 1,000); `--human-readable` (no value); `--summarize` (no value); `--bucket-name-prefix` |
| `aws s3api list-buckets` | `--prefix`; `--max-items` (1 to 500) |
| `aws s3api list-objects-v2` | `--bucket` (required); `--prefix`; `--delimiter` (`/`); `--encoding-type` (`url`); `--max-items` (1 to 500); `--starting-token`; `--page-size` (1 to 1,000) |
| `aws s3api list-object-versions` | `--bucket` (required); `--prefix`; `--delimiter` (`/`); `--encoding-type` (`url`); `--max-items` (1 to 500) |
| `aws s3api head-bucket` | `--bucket` (required) |
| `aws s3api head-object` | `--bucket` (required); `--key` (required) |
| `aws s3api get-object-tagging` | `--bucket` (required); `--key` (required) |
| `aws s3api get-bucket-location` | `--bucket` (required) |
| `aws s3api get-bucket-versioning` | `--bucket` (required) |
| `preview PATH` | `--format` (`text` or `json` or `ndjson` or `csv` or `tsv` or `parquet` or `hex`); `--columns`; `--max-rows` (1 to 500); `--schema` (no value) |

A `PATH` is `s3://bucket/key` or `bucket/key`; `ls` with no path lists buckets.
`--endpoint-url` and `--region` are accepted only when they name the connection's own endpoint and region, and change nothing; `--output`, `--color`, `--no-cli-pager` and `--no-cli-auto-prompt` are accepted and change nothing, with a notice that says so.
A flag given twice, an abbreviated flag, a value that begins with `-` written as a separate word, a `file://` or `fileb://` value and a `--` word are refused; `--prefix=-x` passes a value that begins with `-`.
A key, prefix or bucket-name prefix longer than 1,024 bytes is refused, and so is a word that holds a NUL character.
On a pinned connection, a command that names another bucket is refused, and a bucket listing answers the pinned bucket with no request.

### 5.3 Refused commands

Every refusal comes before any request, and a refused command is never sent and never written to query history.

| Input | Sentence |
|---|---|
| `aws s3 rm s3://sales/2026/orders.csv` | rm writes, and Studio's S3 support reads only in this version: run it with the AWS CLI or your server's own tools. |
| `aws s3 cp s3://sales/2026/orders.csv .` | cp writes, and Studio's S3 support reads only in this version: run it with the AWS CLI or your server's own tools. To read an object here, run preview s3://bucket/key. |
| `aws s3 presign s3://sales/2026/orders.csv` | presign is refused: it signs a URL with this connection's secret key, and anyone who holds the URL can read the object without credentials until it expires. |

| `aws s3api select-object-content --bucket sales --key a.csv` | select-object-content runs SQL on the server, which this version does not: run preview s3://bucket/key to see an object's first rows. |

| `aws ec2 describe-instances` | ec2 is not S3: Studio's S3 console runs aws s3 ls, the aws s3api reads in the provider doc, and preview. |
| `aws preview s3://sales/2026/orders.csv` | preview is Studio's own command, not the AWS CLI's: write it without aws. |
| `aws s3 ls --profile prod` | --profile is refused: the Access key and Secret on the connection sign every request, and Studio reads no AWS profile or credentials file. |
| `aws s3 ls --no-sign-request` | --no-sign-request is refused: a connection with a blank Access key and Secret sends unsigned requests, and one with a key pair signs every request. |
| `aws s3 ls --debug` | --debug is refused: it prints request headers and signatures, which Studio never shows. |
| `aws s3api list-buckets --query Buckets` | --query is refused in this version: Studio shows the whole result as a grid and runs no JMESPath expression. |
| `aws s3api list-objects-v2 --bucket sales --start-after 2026/` | --start-after is refused: with a delimiter some servers skip a whole folder after it, and others return an empty page. Use --starting-token to read on. |
| `aws s3api list-object-versions --bucket sales --page-size 10` | --page-size is refused on list-object-versions: Studio reads one page of versions, at most 500 entries, and does not read on in this version. |
| `aws s3api head-object --bucket sales --key a.txt --version-id 1` | head-object takes no option --version-id: it takes --bucket and --key. |
| `aws s3api head-object --bucket sales --key a.txt --sse-customer-key k` | --sse-customer-key is refused: Studio does not read objects encrypted with a customer-provided key in this version, and a key typed here would be kept in the query history. |

A command refused only on the server, because it names an endpoint, a region or a bucket other than the connection's, is not sent either; history keeps its text whole with the refusal sentence as its error, as it does for every statement the editor accepts.

### 5.5 Result shape

Every command answers one grid.
`ls` on buckets has the columns `creation_date` and `name`; `ls` on objects has `kind`, `last_modified`, `size`, `name` and `key`, folders before objects within each page, and `key` is Studio's addition, the full key, so the next command can be written from it.
`list-buckets` has `Name` and `CreationDate`; `list-objects-v2` has `Kind`, `Key`, `Size`, `LastModified`, `ETag` and `StorageClass`; `list-object-versions` has `Kind`, `Key`, `VersionId`, `IsLatest`, `LastModified`, `Size` and `ETag`; `head-bucket`, `head-object`, `get-bucket-location` and `get-bucket-versioning` answer `Field` and `Value` rows; `get-object-tagging` answers `Key` and `Value` rows.
`s3api` grids write timestamps as ISO 8601 UTC with milliseconds; `ls` grids write the AWS CLI's 19-character form, in UTC.
An ETag is shown with its quotes, as the server and the AWS CLI show it; `get-bucket-location` shows the region the bucket is in, `us-east-1` for an empty answer, where the real CLI prints the raw value.
`--max-items` counts every row the grid shows, folder rows included, where the AWS CLI counts objects only.
`ls --human-readable` writes the AWS CLI's spelling (1,280 bytes is `1.2 KiB`), the Keys panel writes Studio's shared spelling (`1.25 KB`), and the Metadata part and the `s3api` grids write bytes.

A result can carry these notices, each worded as the console states it:

- When the server sent a continuation token for its bucket list: The server holds more buckets than it listed in one answer, and Studio does not ask for the rest in this version: put a bucket's name in the Bucket field of the connection to read it.
- When a listing of a prefix ends with nothing: No key and no folder begins with this prefix.
- When `head-bucket` gets no region header: The bucket exists and this connection may read it: the server sent no region for it.
- When `get-bucket-versioning` gets no Status: Versioning was never turned on for this bucket: S3 answers no Status.
- When `get-object-tagging` finds no tags: The object has no tags.
- When `list-object-versions` holds more versions than the grid shows: The server holds more versions than this page shows: narrow --prefix to see the rest.
- When `head-object` gets more headers than Studio reads: The server sent more headers than Studio reads, so some fields may be missing.

### 5.7 Pagination and the starting token

Only ListObjectsV2 reads on: `ls` on a path and `list-objects-v2` stop at `--max-items` rows (500 by default), at the server's last page, or after 50 requests, and the result's notice gives the `--starting-token` that reads on, in the AWS CLI's own token form, so a token written by either one resumes in the other.
`ls`, which takes no `--starting-token` in the AWS CLI, names the equivalent `list-objects-v2` command instead.
Reuse a token only with the command whose notice gave it: a token from another command, bucket or prefix is not refused by Studio and gets the server's answer, which differs by server.
ListBuckets and ListObjectVersions read one page each and give no token; a bucket listing narrows with `--prefix`, and a version listing with a narrower `--prefix`.
There is no Load More: the next page is a run of the command with the token, so the command text shows exactly what ran, in history too.
A server that sends the same next token twice stops the run with: The server sent the same next token twice, so reading on would repeat a page: Studio stopped.
Report this to the server's maintainers.

### 5.8 Cancellation and the confirmation gate

Cancel aborts every request of the run at once.
The confirmation gate never asks on S3: the console declares no destructive operation, because it runs reads only, and a command is never posted for an AI safety analysis, because it names buckets and keys.

## 6. Schema introspection

Buckets are objects in the tree; folders and objects are walked in the Keys panel.

### 6.1 The object surface

Two kinds: `bucket`, listed in the tree with no container level above it, or the pinned bucket alone, and the object kind, which the Keys panel lists and the Source tab opens.
Objects are listed in the Keys panel and with aws s3 ls in the console.
`listObjects()` lists buckets only; a bucket's count is the listing itself, and objects are never counted.

### 6.2 Object source

`readObjectSource()` opens a bucket or an object in the Source tab.
A bucket shows three parts: the bucket and the region it is signed for, its location, and its versioning state.
An object shows its Metadata part first, then its preview in one to three parts:

1. Metadata: size, ETag (with the `-<parts>` suffix kept as the server sent it), Last-Modified, Content-Type as stored, Content-Encoding as stored, every `x-amz-meta-*` header (a value whose bytes are valid UTF-8 is shown as that text; any other is shown as received), the version id when the server sends one.
2. Preview, chosen by extension, then magic bytes, then a Content-Type hint for printable text with no known extension; Content-Type never selects Parquet.
   Content-Type is only a hint because a server stores whatever the uploader sent: an upload with no type is stored as `binary/octet-stream` on MinIO and the same NDJSON file reads `application/octet-stream` or `application/x-ndjson` depending on the client that wrote it.
   Text, JSON, NDJSON, CSV and TSV show as text or rows; Parquet shows rows through `hyparquet` with Snappy, gzip, zstd, brotli and LZ4 pages; anything else shows as a hex dump.
   A Parquet file whose first row group does not fit the preview's read, decode, leaf-column or value limits shows its schema, row count and column statistics with the sentence the preview module exports.
   An object stored with `Content-Encoding: gzip` (or a `.gz` key) is decoded one layer, up to the decoded-text cap, with the notice the preview module exports; any other Content-Encoding is shown as stored bytes in hex.

A key Studio can list but not address in path style is listed and refused when opened, with its reason.

#### Object preview

Detection order: the key's extension, then the magic bytes `1f 8b` (gzip) and `PAR1` (Parquet), then a Content-Type hint for printable text with no known extension; `preview --format` overrides detection.
Each format reads one range of the object: text, JSON, NDJSON, CSV, TSV and hex one GET; gzip one GET of the stored bytes; Parquet one GET of the tail, a second only when the footer is longer than the tail, then one GET per run of contiguous column chunks.
Every ranged answer is checked against the HEAD: its ETag and total size must match, or the preview says the object changed.
Parquet footers and page headers pass a structural Thrift check and declared-size checks before `hyparquet` reads them, so decompression and value-count bombs are refused.
At most two Parquet previews decode at a time on one Studio server, separate from the request limiter, and a preview that finds the decode queue full is refused with a sentence.
Not decoded: Content-Encodings other than gzip, LZO, Parquet stored under a whole-object gzip, and VARIANT columns.
Legacy LZ4 pages are decoded, but no file from a real writer was measured with them.

The Parquet value and leaf-column limits were measured: each test shape was decoded once in a fresh Node 26 process with a 128 MiB old-space limit, so two decodes fit the image's 384 MiB heap.

### 6.3 Generated commands

No shipped click reaches the generated commands in v1: a bucket or object row opens its Source tab.
For a bucket the generators write `aws s3 ls s3://<bucket>/`, with `aws s3api list-objects-v2` and `aws s3api get-bucket-versioning` lines as comments; for an object they write `preview s3://<bucket>/<key>`, with an `aws s3api head-object` comment.
They take the provider's own path, `[<bucket>]` for a bucket and `[<bucket>/<key>]` for an object.
A key that begins with `-` is written in the `--flag=value` form; a key holding a carriage return or a NUL character gets a comment that says to open it from the Keys panel instead.

### 6.4 The Keys panel

A bucket is chosen in the tree; Browse Keys on its row switches the sidebar to the Keys view with that bucket's top level open, because the sidebar shows the Objects view or the Keys view and never both.
The Keys panel lists that bucket's top level, folders first, then objects with their size; a folder opens its own level, read from the server's CommonPrefixes one level at a time and complete; each level has its own Load more.
With no bucket chosen, the top level lists the buckets as folders, or the pinned bucket alone.
No count is published.
A key the provider can list but not address is listed and refused when opened, with its reason.
A level's Load more cursor is valid in every process that serves the connection, so it survives a restart, an idle eviction and another replica.
The embedded workspace has no Keys panel.

Declared by `getCapabilities()`: separator `/`, cursor `opaque`, pattern `prefix`, totalScope `none`, levels.rootKind `bucket`, defaultCount 500, maxCount 1,000; `containerLevels` is empty, so a key walk refuses a `database` field.

### 6.5 Object edit (#789): nothing to write

S3 declares no editable object kind and no write path; an object's Source tab is read-only.

## 7. Monitoring & health

Test Connection and every connect send one probe, and the answer must be an S3 listing.
With a pinned bucket, the probe is ListObjectsV2 on that bucket with `max-keys=1`, `delimiter=/` and `encoding-type=url`, and its answer must parse as `ListBucketResult`.
With no pinned bucket, the probe is ListBuckets, and its answer must parse as `ListAllMyBucketsResult`.
A connection whose probe did not parse as S3 XML never reads an object, so a host that answers HTTP but does not speak S3 shows no body.
Both probes need the permission browsing needs (`s3:ListBucket` on a pinned bucket), so a key that can browse can always pass the test.
A 403 from the probe never says that the pinned bucket exists.

S3 declares no maintenance operation, and `runMaintenance()` refuses before any request: Studio sends an S3 server no maintenance: this version only reads.

## 10. Error handling

Every failure is one sentence; the rows below are the sentences for a signed connection to `http://localhost:9000` that signs for `us-east-1`, with the bucket `sales` and the key `2026/orders.csv`.
A server message a sentence quotes is cut to 300 characters.

| Server answer | Studio's sentence |
|---|---|
| 403 `SignatureDoesNotMatch` | The server refused the request signature: check Secret access key. A proxy between Studio and the server that changes the Host header or the request path causes the same refusal. |
| 403 `InvalidAccessKeyId` | The server does not know this access key ID: check Access key ID. |
| 403 `AccessDenied` on a bucket | This access key may not list bucket "sales" (s3:ListBucket). The server answers the same way for a bucket that does not exist, so this does not say that bucket "sales" exists. |
| 404 `NoSuchBucket` | The server has no bucket "sales". |
| 404 `NoSuchKey` | The server has no object "2026/orders.csv" in bucket "sales". |
| 400 `AuthorizationHeaderMalformed` naming another region | This server expects requests signed for region eu-central-1, and this connection signs for us-east-1: set Region to eu-central-1. |
| 403 `RequestTimeTooSkewed` | This machine's clock and the server's differ by more than the server accepts: correct the clock on this machine or on the server. |
| 400 `XMinioInvalidResourceName` | The server refuses a name with a . or .. segment or an empty segment, here in the key or the prefix: type it without such a segment. |
| 501 `NotImplemented` on a continuation token | The server refused this page's continuation token: list this folder again from its start. |
| HEAD 403 with no body and no code | This access key may not read object "2026/orders.csv" in bucket "sales" (s3:GetObject). The server answers the same way for an object that does not exist, so this does not say that object "2026/orders.csv" exists. |
| 501 `NotImplemented` on `list-object-versions` | This server does not keep object versions: it answered 501 Not Implemented to ListObjectVersions. |
| Any 3xx | The endpoint answered list buckets with a redirect (HTTP 301), which Studio does not follow. Check that Host and Port name the S3 API, not a web console: MinIO and RustFS serve their consoles on another port. An AWS bucket in another region answers this way when the server does not name the region: set Region to the bucket's region. |

A 403 never says that a bucket or an object exists: MinIO, Silo and RustFS answer a missing bucket and a forbidden one with the same 403.
A missing bucket or object is said only on a 404.
A HEAD error carries no body; on a HEAD 400 or 403 the provider makes one follow-up read to learn the reason, and reports clock skew only from the server's code or its `date` header, never from the status alone, because MinIO and Silo send no code header on skew alone while RustFS and Garage send none on any HEAD error.
A wrong region on a GET names the region the server expects when the server says it; Garage's bare HEAD 400 says to check Region.
A cursor of another shape or scope is refused before any request; a hand-written cursor of the right shape and scope can reach the server, and its 400 or 501 is the continuation-token row.
Refused before any connection, each with its own sentence: an endpoint in a link-local network (section 3.4), where the transport says: Invalid host: this connection never reaches a link-local address or AWS's IPv6 instance metadata address, whatever DB_HTTP_BLOCK_PRIVATE_HOSTS says; plain HTTP to a host that is not this machine without consent (section 4.6): This connection would reach a host that is not this machine over plain HTTP, where anyone on the path can read bucket and object names, listings and previews, and replay a signed request. Choose an SSL mode under SSL / TLS, connect through an SSH tunnel, or tick Connect without TLS. Nothing was sent.; and, with the HTTP egress guard on, a loopback or private address.
A 416 from a ranged read is not an error of this table: the preview reports it with its own sentence (section 6.2).

A server's own message is shown only when Studio's sentence quotes it: a signing-scope refusal that names no other region, a server failure, and an error code Studio does not recognise; it follows Studio's sentence, cut to the length the provider exports, and a text that holds the secret access key or the access key ID in any form Studio sends is withheld whole.
The secret access key never reaches an error, a result, a log line, an audit row or a notice.

## 11. Testing

The tests run with no server; the live fixtures and the live check run by hand.

### 11.1 How the tests work

Each module has its unit test under `tests/unit/db/s3/`, and none mocks a module.
`tests/integration/db/s3-provider.test.ts` replays exchanges recorded from the four servers, so CI needs no server.
`tests/unit/db/s3/provider-doc.test.ts` reads every number and sentence this page quotes back from the code.

### 11.2 Run it

```sh
bun tests/run-tests.ts tests/unit/db/s3/
bun tests/run-tests.ts tests/integration/db/s3-provider.test.ts
```

### 11.3 The live fixtures

`database-compose.yml` holds the four servers, a MinIO with a site region and a Silo with TLS, with their seeds; `docker/s3/README.md` says how to start and seed each, which keys exist and what every seeded object is for.
MinIO is built from source behind its own profile, because MinIO publishes no community image any more.

### 11.4 The evidence harness and the live check

`tests/live/s3-evidence.ts` records the captures the integration test replays, and `tests/live/s3-live-check.ts` runs every row of the acceptance matrix against one target.
Both run by hand, never in CI.
The evidence harness runs under Bun, and the live check under Bun, Node 24 and Node 26.10.0.

## 12. Running an S3-compatible server for Studio

Give Studio a read-only credential scoped to the buckets it should see: Studio cannot tell what a key can do, and read-only is a property of what Studio sends unless the key itself is read-only on the server.
Serve TLS whenever Studio is not on the same machine.
Set a site region on MinIO or Silo (`MINIO_SITE_REGION`) or Garage (`s3_region`) and type the same region in Studio.

## 13. Known limitations

- Connections are read-only: no upload, copy, delete, bucket, versioning or policy change ([D264](../BACKLOG.md#d264-s3-connections-cannot-write)).
- No SQL over files ([D261](../BACKLOG.md#d261-no-sql-over-files-in-an-s3-bucket)).
- No session token, so temporary credentials from STS cannot sign ([D262](../BACKLOG.md#d262-s3-connections-cannot-use-temporary-credentials)).
- Path-style addressing only ([D263](../BACKLOG.md#d263-s3-connections-address-buckets-by-path-only)).
- Verified on MinIO, Silo, Garage and RustFS only; AWS S3 and hosted services are not verified, as section 4.9 says ([D265](../BACKLOG.md#d265-the-s3-provider-is-not-verified-on-aws-s3-or-any-hosted-service)).
- The tree lists every bucket in one folder, with no paging ([U109](../BACKLOG.md#u109-the-object-tree-is-not-paged-so-an-account-with-thousands-of-buckets-lists-them-in-one-folder)).
- No agent execution and no MCP surface ([B104](../BACKLOG.md#b104-s3-compatible-object-storage-has-no-agent-execution-and-no-mcp-surface)).
- Directory buckets, Multi-Region Access Points, Object Lambda and S3 Tables cannot be read, because each needs a signing scheme or an addressing mode Studio does not implement.
- An object encrypted with a customer-provided key (SSE-C) cannot be read.
- Unsigned access is what an empty key pair means; there is no separate anonymous mode.
- Object versions are listed by `aws s3api list-object-versions` only; no version opens in the Source tab.
- A key Studio can list but not address in path style is shown and refused when opened, with its reason.
- A key whose `.` and `..` segments, resolved with empty segments skipped, climb out of its bucket or name the bucket itself is listed but not opened, on every connection and before any request, because a server or proxy that resolves them would read something else.
- MinIO's community edition is archived; the MinIO fixture is a frozen build ([D267](../BACKLOG.md#d267-the-minio-fixture-is-a-frozen-build-of-an-archived-project)).
- Plain HTTP off this machine needs consent, because bucket and object names, listings and previews cross the network in the clear and a signed request is replayable within the server's clock window by anyone who captures it.
- With the HTTP egress guard off, which is the default, a connection reaches any loopback or private host that answers as S3, and reads the objects that host serves to the connection's key; a host whose connect probe does not parse as S3 XML never has an object read (section 7).
  An operator narrows this with `DB_HTTP_BLOCK_PRIVATE_HOSTS` or by seeding the connections and setting `ALLOW_CUSTOM_CONNECTIONS=false` ([SECURITY](../SECURITY.md) "Known limits"); a policy that differs by role is not built ([D270](../BACKLOG.md#d270-the-http-egress-guard-is-the-same-for-every-role)).
- The Bucket field narrows what Studio lists and opens; it is a scope, not an access boundary, and the key's own policy on the server is the boundary.
  A key whose `.` and `..` segments stay inside its bucket is sent unresolved, so a server, or a proxy in front of it, that resolves them reads the object they resolve to.
  Give a seeded connection a key whose policy names the one bucket it should see.
- A Parquet preview that reads the whole fetch budget needs a link of about 7 Mbit/s to finish within the Source tab's 10-second deadline; on a slower link it ends with the timeout sentence, and the console's `preview --columns` or `--schema` reads less.
- A Parquet preview decodes on the server's event loop, at most 2 at a time on one Studio server ([D271](../BACKLOG.md#d271-parquet-previews-decode-on-the-servers-main-thread)).
- A Parquet preview shows at most 128 leaf columns, the leaf-column bound the decode measurement set, and refuses a schema of more than 1,024 elements, eight times it ([D273](../BACKLOG.md#d273-wide-parquet-schemas-are-refused-above-1024-elements)).
- A Parquet schema that gives two children of one group the same name is refused with the schema sentence, because the preview chooses a column and matches its chunks by name.
- A Parquet file whose first row group holds more values than a preview decodes previews fewer columns, or only its schema and statistics when its first column alone holds more values than a preview decodes, as a row group written with pyarrow's defaults of up to 1,048,576 rows can, or is refused when one page declares more values than a preview allows ([D274](../BACKLOG.md#d274-large-parquet-row-groups-preview-fewer-columns-or-none)).
- A CSV, TSV, JSON or NDJSON preview names at most 8,192 columns and only counts the rest, so a column past them cannot be chosen with `preview --columns`.
- Through an SSH tunnel, the signed and sent Host is the local forward, so a server behind the tunnel that routes by Host name is not supported in v1 (row A63's outcome); a far end given as a name is resolved by the SSH server.
- On Garage a bucket can be listed twice, under a global and a per-key local alias, and an empty key pair never works (section 4.8).
- A key beginning with `/` is listed but not opened, and a bucket name Studio cannot address in path style is listed but neither opened nor expanded.
- ListObjectVersions reads one page; GetObjectAttributes is not used.
- ListBuckets reads at most 10,000 buckets, and an account whose bucket list passes 4 MiB or 100,000 XML elements must set Bucket.
- A hand-written Keys panel cursor, like a console `--starting-token`, can start a page at another position inside what the key may list.
- A compressed XML answer from a proxy is refused, not decoded.
- `--query` is not run; `get-object-attributes`, `--start-after` and `--fetch-owner` are refused.
- Keys holding a NUL character or a carriage return are reachable only from the Keys panel, so not in the embedded workspace.
- Completion offers commands, flags and closed values only: the schema an S3 connection reads holds no bucket, because S3 declares no relation kind, so no bucket name is offered, and no folder or key either.
  `--max-items` counts folder rows.
- On Garage, `list-object-versions` and `get-object-tagging` answer 501.
- The AWS-only error answers of section 10 (a cross-region `301`, `InvalidObjectState`) are not verified.

The bullets without a backlog id are exclusions nobody asked to schedule, or server behaviour Studio cannot change.
