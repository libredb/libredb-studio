# S3-compatible object storage Provider

The `s3` type-id: read-only browsing of buckets, folders and objects, object metadata and capped previews over the S3 REST API, verified on MinIO RELEASE.2025-10-15T17-29-55Z, Silo RELEASE.2026-09-16T00-00-00Z, Garage v2.4.1 and RustFS 1.0.1, and not on AWS S3 or any hosted service.
Source: [`src/lib/db/providers/objectstore/s3/`](../../src/lib/db/providers/objectstore/s3/).
Tests: [`tests/unit/db/s3/`](../../tests/unit/db/s3/) and [`tests/integration/db/s3-provider.test.ts`](../../tests/integration/db/s3-provider.test.ts).

## Before you connect

Seven facts decide whether the first connection works.

1. Type the server's S3 API address, not its web console's: Endpoint host and Port, or paste `http://host:port` or `https://host:port` into Endpoint host.
   Where Studio runs decides what to type in Endpoint host:

| Where the server and Studio run | Endpoint host |
|---|---|
| Both on this machine | `localhost` |
| The server on this machine, Studio in Docker | `host.docker.internal`; on Linux, start Studio's container with `--add-host=host.docker.internal:host-gateway` |
| The server elsewhere | its address, over TLS |

2. Studio addresses every object as `<endpoint>/<bucket>/<key>`, path style, and never by a bucket host name, so a server that answers only virtual-hosted requests cannot be read.
3. Region: Studio signs for `us-east-1` unless you type another region. A server that keeps a fixed region refuses a request signed for any other, and only some servers name the region they expect in the error; section 4.4 says which of the verified servers enforce a region and which name it.
4. Credentials: put the access key ID in Access key ID and the secret access key in Secret access key.
   Only the keys you type sign a request: Studio never reads the server's environment, shared credential files or instance role, and with both fields empty it sends unsigned requests, which only a public bucket answers, and Garage answers none.
   Temporary credentials that need a session token cannot be used in this version.
5. Bucket: leave it empty to list every bucket the credential may list, or name one bucket to browse only that one. This is a convenience, not a boundary (section 13).
   MinIO, Silo, Garage and RustFS list a limited key's own buckets; AWS S3 and some hosted services refuse the listing to such a key (not verified here), so name the bucket there.
6. TLS: Studio refuses plain HTTP to a host that is neither this machine nor reached through an SSH tunnel unless you tick Connect without TLS, because bucket and object names, listings and previews cross the network in the clear, and anyone who captures a signed request can send it again for minutes, and on some servers for hours.
7. What this version does not do: write, run SQL over files, sign with temporary credentials, or use virtual-hosted addressing; and it has been verified on MinIO, Silo, Garage and RustFS only, not on AWS S3, a hosted service or any other server.

## 3. Design decisions

Each decision below states the reason for it.

### 3.1 Read-only v1

Studio reads S3 and writes nothing, whatever the connection's Read-only box says.
The client is built over the byte transport's method set of GET and HEAD alone, so no code path can send a write ([row 3.18](../SECURITY.md)).
Writes are a backlog entry ([D264](../BACKLOG.md)), and so is SQL over files ([D261](../BACKLOG.md)).

### 3.2 Only typed credentials sign

A request is signed only with the access key pair typed into the connection.
Studio never reads an environment variable, a shared credential or config file, a container credential endpoint or instance metadata, so a connection never borrows the identity of the machine Studio runs on ([row 3.19](../SECURITY.md)).
With both keys empty the request goes unsigned: that is what an empty pair means, and there is no separate anonymous mode.

### 3.3 Path style and the region

Every request is addressed as `<endpoint>/<bucket>/<key>`, path style, because the shared transport pins one origin per connection and a virtual-hosted request has one origin per bucket.
The Region field names the region every request is signed for; empty means `us-east-1`.
Section 4.4 says which verified server enforces a region and which names the one it expects.

### 3.4 Link-local networks are always refused

Written by Task 7.

### 3.5 The read-only mode

`READ_ONLY_ENFORCED.s3` is true, so a seed may set `readOnly: true` on an S3 connection, and the connection refuses nothing it would not refuse anyway: S3's provider runs reads only.
The dialog says so under the Read-only box: S3-compatible connections are read-only in this version, whether or not this is ticked: Studio sends no write.
A read-only seed that carries the documented default MinIO or RustFS credential is refused at connect, because the mode would promise a boundary the server does not keep.

### 3.6 Machine access

No agent execution and no MCP: `MCP_EXPOSABLE.s3` is false, so a seed with `mcp: true` on an S3 connection fails the whole file, and the provider implements no `queryReadOnly`, so agent execution and MCP `run_read_query` refuse it, because no MCP surface that lists buckets but never returns an object key is designed yet.
Plan mode works: it grounds on the bucket names the tree shows and drafts one console command in an `s3` block, which it never runs; no object key, prefix, size or content reaches the model.
[B104](../BACKLOG.md) records what an MCP surface and agent execution would need.

## 4. Connection

A connection is one S3 endpoint, an optional key pair, a region and an optional bucket.

### 4.1 Configuration fields

| Dialog field | Connection field | Classification | What it is |
|---|---|---|---|
| Endpoint host, Port | `host`, `port` | public | The S3 API endpoint; the default port is the provider's declared `defaultPort`, `9000` |
| SSL mode, CA | `ssl` | public | TLS; a pasted `https://` raises SSL mode without lowering it |
| Access key ID | `user` | public, shown in the clear and part of the connection fingerprint | The access key ID, 3 to 512 characters; outside that range it is refused before any request with the one sentence the provider and the form share; empty with the secret empty means unsigned requests |
| Secret access key | `password` | secret | Never sent to the S3 server: Studio's server signs each request with it |
| Region | `region` (new, S3 only) | public | Defaults to `us-east-1` when empty |
| Bucket | `database` | public | Optional; when set, Studio never lists buckets |
| Connect without TLS | `allowInsecureAuth` | public | The per-connection consent of section 4.6, signed or unsigned alike |
| Read-only | `readOnly` | public | Accepted; Studio reads only whatever it says (section 3.5) |

The dialog's hint under each field:

- Endpoint host: A host name or address, or a pasted http:// or https:// endpoint such as http://localhost:9000, which is split into Host and Port. The endpoint only: a bucket goes under Bucket, never in the address. MinIO and RustFS serve on port 9000 unless configured otherwise, Garage on 3900. If Studio runs in a container, localhost is that container: use host.docker.internal.
- Access key ID: The access key ID. It is stored and shown in the clear, like a user name. Leave both keys empty only for a bucket that allows anonymous reads: Studio then sends unsigned requests, never this server's own cloud credentials.
- Secret access key: The secret access key. Studio's server signs every request with it and never sends it to the S3 server. Fill in both keys, or neither.
- Bucket: Optional. With a bucket here, Studio reads only that bucket and never lists the others, which a key limited to one bucket needs. Empty: every bucket this key can list.
- Region: The region every request is signed for. Empty means us-east-1, which MinIO accepts unless it was started with a region of its own. Garage: its s3_region setting. AWS: the bucket's region.
- Connect without TLS: Ticked, Studio connects to this host over plain HTTP. The secret access key is never sent to this server, but bucket and object names, listings and previewed contents travel in the clear, readable by anyone on the path, and a captured request can be replayed for several minutes. Choose an SSL mode under SSL / TLS, or an SSH tunnel, wherever the server offers one.

Values the provider refuses before any request, with the sentence the dialog and the provider share:

- An access key ID with a space, comma, equals sign or slash: Access key ID must be printable ASCII without spaces, commas, equals signs or slashes, because it is sent inside the signed Authorization header. Nothing was sent.
- An access key ID shorter than 3 or longer than 512 characters: Access key ID holds 3 to 512 characters, because S3 servers issue no shorter ID and it is sent inside the signed Authorization header. Nothing was sent.
- A bucket name Studio cannot address in path style: Bucket must be 1 to 255 letters, digits, dots, hyphens or underscores, starting and ending with a letter or digit. Nothing was sent.
- A region that is not a region name: Region must be 1 to 64 letters, digits, hyphens or underscores, such as us-east-1. Nothing was sent.

The access key ID stays a public field, and it is still withheld from any server text an error quotes (section 10).

### 4.2 Authentication

Fill in both keys to sign every request with AWS Signature Version 4, or leave both empty to send unsigned requests.
One key without the other is refused before any request: Access key ID and Secret access key go together: fill in both to sign requests, or clear both to send unsigned requests. Nothing was sent.
Studio signs with its own SigV4 code over `node:crypto`, signing `host`, `range` when sent, and every `x-amz-*` header it sends, with the payload hash of an empty body.
The dialog warns when the pair is the documented default root credential of MinIO (`minioadmin`) or RustFS (`rustfsadmin`).
Temporary credentials need a session token, which this version cannot send ([D262](../BACKLOG.md)).

### 4.3 TLS

The SSL panel is the shared one: `disable`, `require`, `verify-ca`, `verify-full`, with a custom CA and a client certificate.
TLS mode `require` sends signed requests to an unverified peer.

### 4.4 One endpoint, path style and the region

One connection is one S3 endpoint, and every bucket is addressed under it in path style ([D263](../BACKLOG.md)).
The Region field signs every request for its value, `us-east-1` when empty.

| Server | Region enforced | Region named in the error |
|---|---|---|
| MinIO | No, unless started with `MINIO_SITE_REGION`; then Yes for bucket and object reads | Yes, when a site region is set |
| Silo | No, unless started with `MINIO_SITE_REGION`; then Yes for bucket and object reads | Yes, when a site region is set |
| Garage | Yes, on every request, ListBuckets included: its `s3_region` | Yes on a GET; No on a HEAD, which carries only its status |
| RustFS | No, even with `RUSTFS_REGION` set | No |

### 4.5 SSH tunnel

The dialog offers the SSH tunnel on every S3-compatible object storage connection.
Through a tunnel, the signed and sent Host is the local forward, so a server behind the tunnel that routes by Host name is not supported in v1 (row A63's outcome).
A far end given as a name is resolved by the SSH server, where Studio cannot check it; a far end given as an address literal is checked against the link-local networks of section 3.4 before the tunnel opens.

### 4.6 Plain HTTP off this machine needs consent

Studio refuses plain HTTP to a host that is neither a loopback address nor reached through an SSH tunnel, signed or unsigned alike, unless the connection's Connect without TLS box is ticked:
This connection would reach a host that is not this machine over plain HTTP, where anyone on the path can read bucket and object names, listings and previews, and replay a signed request. Choose an SSL mode under SSL / TLS, connect through an SSH tunnel, or tick Connect without TLS. Nothing was sent.
The secret access key never crosses the network either way; what crosses it in the clear is every name, listing and preview, and a signed request anyone who captures it can send again while the server's clock window lasts.

### 4.7 Pasting an address

Endpoint host takes a pasted `http://` or `https://` address and splits it into Host and Port; `https://` raises an SSL mode of `disable` to `verify-system`, and `http://` keeps the mode.
An address with a path is refused, because a bucket goes under Bucket; an `s3://bucket/key` URI names an object, not an endpoint, and is refused too.
The connection-string box offers no S3 mode.

### 4.9 What is not verified

Studio has not been run against AWS S3, any hosted S3-compatible service, or any self-hosted server other than the four of section 4.8, such as Ceph RGW or SeaweedFS, so none of them is claimed.
These behaviours exist on AWS and were never exercised:

- a `301 PermanentRedirect` for a bucket in another region, which Studio refuses rather than follows;
- virtual-hosted addressing on real DNS, and bucket names with dots over TLS;
- temporary credentials from STS, which need a session token Studio cannot send;
- ListBuckets paging, which AWS requires above 10,000 buckets and every verified server ignores;
- objects in an archive storage class, which answer a read with `403 InvalidObjectState`;
- the checksum headers AWS SDKs send by default;
- keys with `.`, `..` or `//` segments, which AWS accepts and MinIO, Silo and RustFS refuse.

Cloudflare R2 signs for the region `auto`, and DigitalOcean Spaces asks clients to sign for `us-east-1`; neither was tried.
[D265](../BACKLOG.md) is the follow-up.

## 7. Monitoring & health

Test Connection and every connect send one probe, and the answer must be an S3 listing.
With a pinned bucket, the probe is ListObjectsV2 on that bucket with `max-keys=1`, `delimiter=/` and `encoding-type=url`, and its answer must parse as `ListBucketResult`.
With no pinned bucket, the probe is ListBuckets, and its answer must parse as `ListAllMyBucketsResult`.
A connection whose probe did not parse as S3 XML never reads an object, so a host that answers HTTP but does not speak S3 shows no body.
Both probes need the permission browsing needs (`s3:ListBucket` on a pinned bucket), so a key that can browse can always pass the test.
A 403 from the probe never says that the pinned bucket exists.

Written by Task 6.

A server's own message is shown only when Studio's sentence quotes it: a signing-scope refusal that names no other region, a server failure, and an error code Studio does not recognise; it follows Studio's sentence, cut to the length the provider exports, and a text that holds the secret access key or the access key ID in any form Studio sends is withheld whole.
The secret access key never reaches an error, a result, a log line, an audit row or a notice.
